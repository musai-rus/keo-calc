## Как работать с заданием

1. Любая реализация начинается с чтения `AGENTS.md`, `INSTRUCTION.md` и соответствующего файла из `tasks/` (для Revit — `tasks/KEO_REVIT.md`).
2. ТЗ содержит требования и критерии приёмки; GitHub Issue содержит этапы, исполнение, риски и ссылки на PR; Slack — обсуждения и краткие отчёты. Не создавать конкурирующие копии требований.
3. В Revit-направлении использовать этапы D0–D6 из ТЗ: у задачи должны быть зависимости, условие завершения, состояние и доказательство. Сохранять существующие Issue #13/PR #15 и тестовую копию RVT; не создавать дубликаты. До объединения PR рабочая редакция ТЗ находится в feature-ветке, не в `main`.
4. Решения, согласованные с автором и меняющие рамки проекта, отражать в ТЗ **до или вместе** с реализацией и датировать в журнале изменений файла. Новые гипотезы помечать как эксперименты, а не принятые требования.
5. В PR указывать затронутые пункты задания, тесты, известные ограничения. Изменение расчётного ядра, принятых норм и перенос экспериментального кода в `main` требуют отдельного согласия автора.
