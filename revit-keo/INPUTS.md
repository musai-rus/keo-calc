# Поля существующего калькулятора для Revit

Техническая карта к [ТЗ v0.3.0, разделам 2–4](../tasks/KEO_REVIT.md), не отдельное ТЗ и не новая методика. Имена сверены с текущими `KEO.defaultState`, `sideInput`, `topInput`, `b2Input`, `rhoOf` в `model.js`. Сначала выбирается поддерживаемая схема; Revit запрашивает только используемые ею данные. Числовые единицы геометрии в state — метры, площади — м²; преобразование единиц Revit фиксируется в evidence.

| Что нужно | Поля state v:1 | Когда / откуда |
|---|---|---|
| Схема и нормативное назначение | `mode`, `lightSys`, `roomId`, `normManual`, `hpManual`, `rtManual` | Для выбранного расчёта. Назначение из настроенного параметра с проверенным сопоставлением справочнику или явного выбора. Ручная норма/точка/рабочая плоскость — с основанием. `roomId` — код назначения калькулятора, **не** Revit ElementId/номер Room. |
| Климат | `region`, либо `groupManual=true` + `group` | Выбор региона из справочника или подтверждённая группа. Не выводить группу из имени файла/адреса по догадке. |
| Условия эксплуатации и отражение | `env`, `glassMult`, `rhoMode`; условно `rho`, `rhoBasis`, `rhoGeo`, `rhoSurf`, `rhoRows` | Существующие режимы калькулятора. При выбранном нормативном режиме `rhoMode=default` не нужно исследовать все материалы. Режим по поверхностям требует соответствующих площадей/отражений, ручной — значения и основания. |
| Боковой свет: помещение и точка | `side.walls[].dp`, `bp`, `dst`, `ds`, `orient`; `lt` при ручной точке | Параметры с проверенным смыслом или необходимые размеры/ориентация относительно истинного севера. Число стен в JSON не доказывает число физических световых сторон. `H` нужен для автоматических площадей в режиме отражения по поверхностям; он не является обязательным обмером для каждого бокового расчёта. |
| Боковые проёмы | `windows[].hpd`, `ho`, `bo`, `s` | Подоконная отметка, высота, ширина и смещение в системе расчётного фасада. Семейство и host нужны для надёжной связи с Room, если используется автоматическое извлечение. Имя семейства не является правилом классификации. |
| Пропускание и местное затенение | Стена: `t1`, `t1c`, `t2`, `t4`, `t5`, `kType`, условно `kDepth` либо `kManual`/`kBasis`; исключения проёма: `t2m/t2o`, `tau0m/tau0o/tau0b`, `Km/Ko/Kb` | По справочникам/паспортам/явному вводу в уже поддерживаемых режимах. Не выводить τ из отображаемой прозрачности материала Revit. При ручном τо не извлекать заменённые им отдельные коэффициенты из BIM. Общие поля, которые читает/валидирует ядро, остаются корректными служебными значениями state с явным указанием, что они не использованы. |
| Противостоящие здания | `buildings[].l`, `Hp`, `a`, `off`, `rhoF` | Только если нужны выбранной схеме. Пустой список означает подтверждённое отсутствие учитываемых препятствий, а не сбой поиска. Связь/фаза/ориентация проверяются для релевантных объектов. |
| Верхний свет: помещение и разрез | `top.sys`, `L`, `B`, `H`, `spans`, `l1`, `y0`, `nPts`, `nPtsBasis`, `coordOrigin` | Параметры/необходимая геометрия помещения; разрез и число точек по существующей политике ядра. Координаты JSON хранятся от угла; `coordOrigin` меняет представление в интерфейсе. |
| Шахтные/зенитные фонари | `top.types[].shape`, `dv/dn` для круга **либо** `av/bv/an/bn` для прямоугольника; `hsf`, `lanterns[].x/y`, `refl`, `rhoW`, `t1…t4`, `net`, `tilt`; условный `KcManual` | Только выбранная поддерживаемая форма, необходимые размеры верхнего/нижнего отверстия, высота шахты, координаты, используемые коэффициенты. Не подменять неизвестную форму квадратом, не требовать размеры неиспользуемой формы. |
| Фонари-надстройки | `top.b2[].kind`, `b`, `hst`, условно `ho`, `beta`, `face`, `ystart`, `ylen`, `pieces`, `pitch`, `xs`, `CNrow`, `t1…t4`, `net` | Поля выбранного типа Б.2, которые уже принимает калькулятор. Сложная неподдерживаемая форма получает диагностику; её не заменяют произвольной надстройкой. |
| Комбинированный свет | Активные боковые и верхние поля + `comb.wallSide` | В пределах текущего ядра: одна используемая боковая стена, общие размеры `top.L/B`. Автоматически отбрасывать дополнительные значимые световые стороны нельзя. |
| Подпись и связь с BIM | `meta`; отдельно evidence с document/Room UID, фазой/вариантом/путём связи, fingerprint | Номер/имя/уровень — подписи и фильтры. Идентичность не зависит от номера. В расчётном state нет тел, материалов и всей сцены Revit. |

## Правила извлечения и проверки

1. Для каждого активного поля хранить путь в state, значение/единицу, источник (`parameter`, `geometry`, `user`, `calculator-rule`), устойчивую ссылку/ID-GUID параметра или основание ввода, преобразования, статус проверки. Не требовать пользователя подтверждать каждое надёжно извлечённое число отдельно.
2. Параметр допустим после проверки его смысла: общие «Ширина/Высота» семейства не всегда являются размерами расчётного проёма. Достаточные параметры предпочтительнее подробной обработки тел. Если параметров нет, выполнять только измерения, необходимые конкретному полю. Явный ввод разрешён и отражается в карточке.
3. Размер проёма должен соответствовать смыслу `bo/ho` в существующем калькуляторе, включая принятый там обмер коробки и учёт переплётов через коэффициенты. Не заменять его автоматически чистой площадью стекла и не учитывать рамы дважды. Подробная прозрачная геометрия требуется лишь для разрешения конкретной неоднозначности, которую нельзя закрыть параметрами/проверенным вводом.
4. Нет обязательной выгрузки всех граней, материалов, тел, кривых и всей сцены. Диагностика D2 остаётся инструментом исследования. Неизвестный материал/кривая вне зависимостей активных полей — предупреждение, не общий запрет расчёта.
5. Неизвестное значение, применимость схемы или полнота нужного затенения — конкретная причина серого статуса этого Room. Надёжные остальные Rooms продолжают обработку. Отсутствие данных не равно нулю, отсутствию препятствий или подтверждённому значению по умолчанию.
6. Значения из `defaultState()` служат структуре/синтетическим примерам; они не становятся подтверждёнными фактами реальной модели. Неактивные секции state могут содержать служебные значения для совместимости импорта; они не создают требований к извлечению из BIM.
7. В рабочем коде запрещены номера тестовых Rooms, ID тестовых элементов, названия семейств/этажей и пути конкретного проекта. Параметры сопоставляются через настройки и ID/GUID, а не правила для одной модели. Защитные пути тестовой RVT и выбор тестового Room существуют только в приватной конфигурации испытаний.

`runner/active-inputs.cjs` проверяет наличие основных активных полей до миграции; числовая валидация остаётся в ядре. Эта проверка не заменяет адаптер, проверку применимости или подтверждение происхождения. D2.2/D4 должны сформировать и проверить реальные входы; runner выдаёт только предварительный результат.
