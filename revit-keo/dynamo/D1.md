# D1 — чтение выбранного Room и проверка контуров

Минимальный D1 выполнен на MRM для одного Room в Main Model существующей standalone копии. Это диагностический срез: он не извлекает световые проёмы, не рассчитывает КЕО и не подтверждает полноту всей геометрии. Требования — [ТЗ](../../tasks/KEO_REVIT.md), доказательства — [протокол D1](../validation/2026-10-23-build.md#d1-room-и-нативные-контуры).

## Состав и зависимости

- `d1_capture.py` — выбор по фазе, ID/GUID параметра и точному типизированному значению, явный UniqueId одного Room, нативные Line/Arc, источники границ, уровень/высоты, север, ссылки и диагностика.
- `KEO_D1_RoomEvidence.dyn` — Manual, три входа (путь конфигурации, Boolean, номер запуска), PythonNet3 и Watch. Пустой путь и False по умолчанию. Сгенерирован из проверенного D0-каркаса.
- `build-d1.cjs` — встраивает D0 host/guards и D1-код, записывает SHA-256 полного bundle. Никаких внешних Python-пакетов, sys.path или загрузки нашей C# DLL.
- `validate_d1.py`, `curve_metrics.py` — независимые офлайн-проверки замыкания, пересечений/касания, вложенности, площади, периметра и габаритов горизонтальных Line/Arc. Дуги обрабатываются аналитически, без хорд или полигональной аппроксимации.
- `test_d1_capture.py`, `test_validate_d1.py`, `test_curve_metrics.py` — 22 проверки D1. Вместе с 9 D0 — 31 тест.

Среда: Revit 2027.3/build 27.3.0.28, DynamoCore 4.2.1.5887, PythonNet3 engine 1.4.8.0, CPython 3.11.0, Python.NET 3.1.0.0, .NET 10.0.13. На другой установке повторить D0. Player-сценарий не проверен.

## Последовательность запуска

1. Использовать прежнюю согласованную тестовую standalone RVT. Она должна быть сохранена и не иметь несохранённых изменений. Сам D1 не сохраняет модель и не отменяет чужие изменения.
2. Создать локальную конфигурацию по `config.d1.example.json`: точный путь копии, независимо проверенный SHA-256, build, путь частного журнала `.jsonl`, ID одного реального Room для первоначального просмотра параметров. Все реальные пути, ID, координаты, конфигурацию и журнал хранить вне Git.
3. Открыть граф в Dynamo, самостоятельно ответить на запрос доверия внешнему графу, если он появляется. Ввести путь конфигурации. False + Run даёт CANCELLED до обращения к API. True + Run в режиме `inventory` выдаёт фазы, Rooms и параметры выбранного образца. Numeric ID используется только для этого просмотра; идентичность дальнейшего захвата — UniqueId + документ + фаза.
4. Из inventory выбрать точные `phase_uid`, `selected_room_uid`, `parameter={"kind":"id","key":"DECIMAL_PARAMETER_ID"}` либо `{"kind":"guid","key":"SHARED_PARAMETER_GUID"}`, `value`. Поменять `mode` на `capture`, убрать `sample_element_id`, добавить эти четыре поля. Имя параметра — подпись, не ключ отбора. Значение String/Integer/Double должно иметь соответствующий JSON-тип; Double — точное внутреннее значение из inventory, ElementId — десятичная строка. Локализованные строки чисел не используются как входы.
5. Изменить Run number и выполнить граф. Это нужно и после изменения конфигурационного файла: Dynamo не следит за его содержимым и может использовать кэш. Новый runId подтверждает фактический запуск.
6. Успешное **чтение** — `CAPTURED_DIAGNOSTIC`, `documentUnchanged=true`; это не приёмка геометрии или норм. В Watch показывается сводка, полный payload записан в частный журнал. Если выбранный UniqueId не входит ровно один раз в результат фильтра данной фазы — REFUSED, автоматической подмены комнаты нет.
7. Для офлайн-сверки выделить конкретную запись capture из JSONL в частный JSON и выполнить `python -B revit-keo/dynamo/validate_d1.py PRIVATE_CAPTURE.json`. METRICS_MATCH подтверждает согласованность описанных контуров с Room.Area/Perimeter в пределах численных допусков; флаги полной геометрической/нормативной приёмки остаются false.
8. Повторить захват с новым номером: payloadSha256 должен совпасть при неизменных данных. Вернуть False, проверить отмену и независимо сверить хеши исходного и тестового RVT. Не сохранять RVT или граф с приватными входами в публичный репозиторий.

## Область данных и ограничения

Схема `keo-dynamo-d1-evidence/v1` — отдельный диагностический формат. Он использует принципы [Room evidence контракта](../../research/revit-room-export/CONTRACT.md), но не выдаётся за полный SDK codec `keo-room-evidence/0.1` или вход `v:1` калькулятора. Формулы КЕО не реализованы здесь.

- Координаты — internal feet, площади ft², объёмы ft³; перевод 0.3048 задан явно. ElementId хранится десятичной строкой; root document key — ProjectInformation.UniqueId, отдельно записан файловый baseline. Имя/номер не являются идентификатором.
- Room phase читается из `ROOM_PHASE_ID`, не из CreatedPhaseId или имени фазы. Сохраняются option/lifecycle, ограничения высот и Level.ProjectElevation/вычислительная высота. Сам граф не переключает фазу/вариант.
- Все GetBoundarySegments(Finish, StoreFreeBoundaryFaces=true) сохранены в API-порядке. Line имеет точные концы, Arc — концы/центр/оси/радиус/диапазон; прочие кривые дают unsupported. Неизвестный генератор не становится стеной. Room separator явно помечен семантической границей.
- Отдельная проверка определяет вложенность; первый API loop не принимается автоматически за внешний. Плановая граница и точка Room не являются срезом или расчётной точкой на высоте 1,2 м.
- Север записан из ProjectLocation.GetProjectPosition(XYZ.Zero), но повторно не применяется к internal координатам. Для экземпляров RVT предусмотрены GetTransform и GetPhaseMap; реальный проход не содержал таких экземпляров, loaded-link/phase-map сценарии ещё не испытаны. Linked Room, design options и вложенная связанная геометрия не приняты.
- Кроме RVT instances перечисляются все верхнеуровневые ExternalFileReferences: CAD и справочные таблицы. Статус доступности не доказывает релевантность расчёту. Вложенные ссылки этим перечнем не покрыты.
- Фильтр Rooms не ограничивает перечень ссылок. Фактическая геометрия окружающих объектов, остекление/затенение относятся к D2.
- Снимки IsModified/DocumentVersion/SHA-256 контролируют границы прохода; нет блокировки писателей или наблюдения DocumentChanged. Цельность нескольких связанных документов этим срезом не доказывается. Все geometry/model/normative acceptance flags остаются false.
- Допуски сравнения заданы до сверки: 1e-7 ft для координат, 1e-6 ft²/1e-6 relative для площади, 1e-6 relative для периметра. Это численные допуски, не доказательство точности BIM. Самопересечения, касания, разрывы и неподдержанные типы не исправляются ради совпадения.

## Проверки исходников

```sh
node revit-keo/dynamo/build-graph.cjs --check
node revit-keo/dynamo/build-d1.cjs --check
python -B -m unittest discover -s revit-keo/dynamo -p 'test_*.py'
```

После изменения D0/D1 исходников пересобрать D1 через `node revit-keo/dynamo/build-d1.cjs` и повторить релевантные проверки. Фактический runtime в текущем проходе проверен заменой Python-кода в уже открытом трёхвходовом D0-каркасе на точный D1 bundle. Сохранённый D1 `.dyn` с тем же кодом/входами проверен генератором; отдельное открытие этого файла и Player-сценарий не испытывались. Приватные входы при закрытии рабочего сеанса не сохранялись в D0.
