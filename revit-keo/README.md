# «КЕО для Revit» — прототип через Dynamo

**Статус на 23.10.2026:** основной следующий путь — Dynamo/Python/Revit API → проверяемая геометрия → существующее JS-ядро. Архитектура обновлена до [ТЗ v0.2.0](../tasks/KEO_REVIT.md); граф Dynamo, Python-адаптер и локальный runner ещё не реализованы/не испытаны. Текущая задача — **D0**, проверка установленной среды и read-only запуск на **уже подготовленной standalone копии RVT**. Учёт работ: [Issue #13](https://github.com/musai-rus/keo-calc/issues/13), изменения: [PR #15](https://github.com/musai-rus/keo-calc/pull/15), ветка `feature/revit-keo-prototype`. До объединения PR рабочее ТЗ находится в этой ветке.

Computer Use восстановлен, через MCP прочитаны реальные Rooms. Собственный C#-срез собран и зарегистрирован, но запуск команды заблокирован Windows до нашего `Execute` (`0x800711C7`). Это не успешный запуск экспортера или Dynamo. Подробности — [протокол сборки и последующего прохода](validation/2026-10-23-build.md). Защита Windows не менялась.

## Целевой сценарий и следующий шаг

Граф управляет чтением Room и преобразованием геометрии; Python может реализовывать сложные геометрические алгоритмы. Расчётные формулы остаются в исходных `engine.js`, `data.js`, `model.js`. Локальный runner должен получать подтверждённый `state v:1`, вызывать это же ядро и возвращать результат. Ручной импорт JSON нужен для контрольной сверки; целевой сценарий выполняет всю цепочку без ручного переноса вычисленных полей.

На D0 проверить фактические версии Dynamo/Player/Python, допустимый API-контекст и зависимости, сохранить воспроизводимый граф/скрипт и показать чтение контекста тестовой модели, отмену и повтор. Проверить активный документ, `IsModified` до/после и неизменность RVT. Использовать ручной запуск, без транзакций записи, узлов изменения модели и `Save/SaveAs`. Исходник не трогать; новые копии модели на каждый прогон не создавать.

Последовательность и условия завершения — D0–D6 в [разделе 8 ТЗ](../tasks/KEO_REVIT.md). После среды: Room/evidence → геометрия и JS runner → один Room end-to-end → Player/отчёт, пакетная работа и отдельный write-back → расширение покрытия. Граф и читаемые Python-исходники следует хранить вместе в Git, с точными версиями и инструкцией запуска. Размещение будущего Dynamo-кода — `revit-keo/dynamo/`; сейчас такого реализованного среза нет.

C#-подпись, установщик и WPF/WebView2 отложены; загрузка нашей DLL не нужна для D0. Не загружать заблокированную DLL через Dynamo. Работу установленного Dynamo и JS runner всё равно требуется проверить: смена архитектуры сама по себе не доказывает их доступность.

## Что уже есть в этой ветке

1. `native/RoomFilterCaptureCommand.cs` — экспериментальная команда `IExternalCommand` с `TransactionMode.ReadOnly`. Исходник реализует выбор фазы, ID/GUID параметра и точного значения, подсчёт Rooms и сохранение сырого evidence через `research/revit-room-export/sdk/CaptureCommand.cs`. Runtime-проверка нашего кода не пройдена.
2. `native/Keo.RevitPrototype.csproj` — Revit **2027.3 / API 27 / .NET 10**; флаг `KEO_REVIT_2027` оставляет исследовательский SDK 2026 отдельным target. Сборка на MRM: **0 ошибок, 2 MSB3277** (Microsoft.VisualBasic / System.Drawing). Совместимость выполнения не подтверждена.
3. `bridge.js` — автономный JS-модуль: сырой неподтверждённый снимок даёт **серый PENDING** с причинами. Для явно введённого синтетического `state v:1` проверяется сериализация/пересчёт текущими `KEO.migrate()`/`KEO.compute()`. Это основа контракта, не готовый автоматический расчёт по BIM и не Dynamo runner.
4. `test-bridge.js` — проверки на неизменённом реальном ядре: совпадение результата до/после JSON, серые статусы для недостоверного evidence. Они не заменяют тест Revit API.

**Ещё не реализовано/не принято:** Dynamo-адаптер; фактическая светопропускающая геометрия окон/витражей/фонарей и 3D-затенение; доказанный mapping → state; автоматический вызов ядра из Dynamo; карточка/Player-сценарий, PASS/FAIL, shared-параметры, виды/марки/спецификации, write-back и stale. Выявленные отсутствующие связи нельзя игнорировать при подтверждении геометрии. Не выдавать MCP-снимок с линеаризованными границами за точные нативные кривые.

## Сохранённый C#-срез: сборка и отложенная проверка

Эти шаги относятся к C#, не являются текущей задачей D0 и не обходят установленную блокировку Windows.

На Windows с официальными Revit 2027.3 / .NET 10 SDK зафиксировать source SHA:

```powershell
$commit = (git rev-parse HEAD).Trim()
dotnet build revit-keo/native/Keo.RevitPrototype.csproj --configuration Release -p:RevitInstallDir="C:\Program Files\Autodesk\Revit 2027" -p:SourceCommit=$commit
```

На MRM подтверждены Revit file version `27.3.0.28`, build label `20260907_1515(x64)`, API assemblies `27.3.0.0`, .NET SDK `10.0.402`; прямое чтение `Application.VersionBuild` нашим аддином не выполнено. При другой версии не подменять DLL; нужна проверенная конфигурация. Offline NuGet-профиль сборки описан в протоколе.

Шаблон `native/Keo.RevitPrototype.addin.example` не устанавливает ничего автоматически. Регистрация на MRM уже выполнена в пользовательском каталоге Revit Addins 2027; повторная установка сейчас не требуется. При будущем переносе сначала проверить целевой хост и разрешение на установку, использовать пользовательский каталог `%AppData%\Autodesk\Revit\Addins\2027`, не менять системную защиту. Вопрос доверия/подписи и runtime-загрузки остаётся отдельной задачей.

C# capture ограничен сохранённым standalone документом: workshared/cloud/linked root, dirty/unsaved document и design options не поддержаны этим срезом. Простая файловая копия workshared RVT не делает его standalone. Для текущих тестов уже существует подходящая отдельная копия; не отсоединять открытый исходник и не создавать повторные копии. Эти ограничения C# не доказывают полноту будущего Dynamo-адаптера: профиль его поддержки нужно зафиксировать и проверить отдельно.

После решения вопроса загрузки отдельно проверить выбор/отмену команды, read-only capture, install/uninstall и неизменность документа/файла. Сырой JSON не является принятым state калькулятора. Логи, source SHA и независимые сверки сохранять без публикации приватной модели, геометрии и пользовательских путей.

Контракты для переиспользования: [SDK.md](../research/revit-room-export/SDK.md) и [CONTRACT.md](../research/revit-room-export/CONTRACT.md). Факты проверки вносить в существующий протокол, текущий статус — в ТЗ и Issue #13.
