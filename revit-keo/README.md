# «КЕО для Revit» — начальный экспериментальный прототип

**Статус на 23.10.2026:** подготовлены исходники команды для выбора Room по параметру и чтения evidence из Revit, а также диагностический JS-мост для проверки совместимого JSON на **исходном расчётном ядре**. Никаких утверждений о работающем установленном аддине, точности 3D-геометрии или нормативном КЕО делать нельзя: **не было локальной сборки .NET/Revit SDK и запуска на Windows MRM**. Источник истины по требованиям — [`tasks/KEO_REVIT.md`](../tasks/KEO_REVIT.md), план работ — [Issue #13](https://github.com/musai-rus/keo-calc/issues/13).

## Что делает этот срез

1. `native/RoomFilterCaptureCommand.cs` — *source-only*, команда `IExternalCommand` с `TransactionMode.ReadOnly` в Revit. Выводит фазы, уникальные имена **и ID/GUID** параметров реальных Rooms, значения для выбранного параметра и число Room при точном совпадении; сохраняет сырой evidence JSON через существующий строгий адаптер `research/revit-room-export/sdk/CaptureCommand.cs`.
2. `native/Keo.RevitPrototype.csproj` — зафиксированная исходная конфигурация Revit **2026 API 26 / .NET 8**, объединяющая команду выбора и существующий SDK capture. Другие версии Revit не объявлены совместимыми; сборка не проверена.
3. `bridge.js` — отдельный автономный JS-модуль: на сыром снимке возвращает **серый `PENDING`**, перечисляет причины неподтверждения геометрии и нормы. Для **явно введённого тестового** `state v:1` проверяет пересчёт/сериализацию с помощью текущего `KEO.migrate()`/`KEO.compute()` без копирования формул. Диагностический state нельзя выдавать за автоматический расчёт по BIM.
4. `test-bridge.js` — реальное ядро проекта запускается без модификации; проверяются одинаковые результаты до/после JSON и серые статусы для недостоверного evidence. Синтетика не заменяет тест Revit API.

**Ещё не реализовано:** извлечение фактической светопропускающей площади витражей/окон/фонарей и 3D-затенения; доказанный mapping → `state`, нормативный расчёт по геометрии, UI карточки, `PASS/FAIL`, shared-параметры, виды/марки/спецификация, write-back, устаревание на изменённом RVT. Не подменять их успехом этого первого среза.

## Подготовка реальной проверки на отдельной копии модели (Windows MRM)

1. Определить `Autodesk Revit` точную версию **и build**, API DLL и установленный .NET SDK. Прототип рассчитан только на **2026, API 26, .NET 8**: если другая версия/runtime, **остановиться** и подготовить отдельную конфигурацию с проверкой; не переименовывать DLL для обхода несовместимости.
2. Создать **сохранённую локальную самостоятельную копию RVT** для теста. Работающий исходник не изменять. Этот срез не поддерживает `workshared`, cloud, linked root, unsaved/dirty document или design options. Для рабочих проектов со связями нужен следующий этап, а не отключение проверок.
3. На Windows с официальной установленной Revit 2026 и `.NET 8 SDK`, в клоне репозитория зафиксировать проверяемый SHA сборки:

   ```powershell
   $commit = (git rev-parse HEAD).Trim()
   dotnet build revit-keo/native/Keo.RevitPrototype.csproj --configuration Release -p:RevitInstallDir="C:\Program Files\Autodesk\Revit 2026" -p:SourceCommit=$commit
   ```

   Здесь эта команда **не выполнялась**. Папка SDK/целевая конфигурация проверяются по факту. Исходный `Capture` также проверит SHA-256 сохранённого RVT, `DocumentVersion`, фазу и версии API/build.
4. На **изолированном тестовом хосте**, после проверки сборки и согласия на установку, создать `.addin` из `native/Keo.RevitPrototype.addin.example`, подставив фактический путь к DLL. Разместить только в каталоге аддинов нужной тестовой версии Revit; исходник шаблона автоматически не устанавливает ничего.
5. Запустить команду из Revit `Add-Ins → External Tools`, явно выбрать фазу, параметр и значение, увидеть количество/UID Rooms, сохранить **новый** `*.json`. Файл является *сырой диагностикой*, не готовым JSON для калькулятора. Никаких транзакций, `Save/SaveAs` или изменения RVT команда не делает.
6. Сохранить build log, точный source commit и RVT hash, сырые примеры (без публикации приватной модели), снимки параметра/фазы/границ и независимую проверку. Ошибка или несогласованная связь — повод остановиться, не дополнять нулями.

Для исходного read-only SDK см. [`SDK.md`](../research/revit-room-export/SDK.md) и [`CONTRACT.md`](../research/revit-room-export/CONTRACT.md). После native-прогона обновить `tasks/KEO_REVIT.md` и Issue #13. Следующий шаг — проверяемая геометрия проёмов/затенения и только затем переход от серого к зелёному/красному.
