# «КЕО для Revit» — прототип через Dynamo

**24.10.2026, [ТЗ v0.3.0](../tasks/KEO_REVIT.md):** выбранный Room → только нужные калькулятору входы → неизменённое JS-ядро → карточка/экспорт → цвета помещений и марки на отдельном плане. D0 и минимальный D1 выполнены. Карта входов D2.1 и runner D3.1 готовы; пять синтетических вариантов дважды вызваны из Dynamo. Реальные входы D2.2/D4 и запись D5 ещё открыты.

Работа ведётся в существующих [Issue #13](https://github.com/musai-rus/keo-calc/issues/13)/[PR #15](https://github.com/musai-rus/keo-calc/pull/15), ветка `feature/revit-keo-prototype`. До объединения PR читать ТЗ из этой ветки.

## Ближайший результат

[Карта входов](INPUTS.md) задаёт поля выбранной схемы, источники и условную необходимость. Сначала проверенные параметры; геометрия — только для нужных измерений/проверок; явный ввод сохраняется с основанием. Детальное исследование всех граней/материалов не является обязательным шагом. Рабочий код не зависит от номеров Rooms, семейств, этажей, ID и путей конкретного проекта.

Следующий шаг D2.2 — сопоставить необходимые входы первого поддерживаемого реального Room, затем D4: автоматический вызов ядра и сверка JSON ручным калькулятором. После этого D5: несколько Rooms, карточки, предпросмотр и отдельная запись цветов/марок. Неизвестные обязательные данные дают причину серого статуса одного Room и не останавливают остальные.

## Запуск и ограничения

`runner/client.py` вызывает явный абсолютный путь к локальному Node; runtime пользователя не должен зависеть от Codex/MCP. В испытании использован уже установленный Node `24.19.0`; упаковка для другого компьютера ещё открыта. Команды/конфигурация — в [runner/README.md](runner/README.md).

Использовать прежнюю standalone копию RVT. D0–D4 не записывают/не сохраняют модель. Историческое разовое разрешение на подготовительное сохранение было использовано в D0 и не разрешает будущие сохранения. Новых копий на каждый запуск не создавать. Любой write-back — после предпросмотра и отдельного разрешения.

`bridge.js` и runner возвращают только серый предварительный статус: число из ядра само по себе не подтверждает исходные данные Room или нормативную применимость. Частные конфигурации/геометрия/модели остаются вне Git. Основное ядро, Viewer и исходный RVT не меняются.

## Сохранённый C#-срез: сборка и отложенная проверка

Эти шаги относятся к C#, не являются текущей задачей Dynamo и не обходят установленную блокировку Windows.

На Windows с официальными Revit 2027.3 / .NET 10 SDK зафиксировать source SHA:

```powershell
$commit = (git rev-parse HEAD).Trim()
dotnet build revit-keo/native/Keo.RevitPrototype.csproj --configuration Release -p:RevitInstallDir="C:\Program Files\Autodesk\Revit 2027" -p:SourceCommit=$commit
```

На MRM подтверждены Revit file version `27.3.0.28`, build label `20260907_1515(x64)`, API assemblies `27.3.0.0`, .NET SDK `10.0.402`; прямое чтение `Application.VersionBuild` нашим аддином не выполнено. При другой версии не подменять DLL; нужна проверенная конфигурация. Offline NuGet-профиль сборки описан в протоколе.

Шаблон `native/Keo.RevitPrototype.addin.example` не устанавливает ничего автоматически. Регистрация на MRM уже выполнена в пользовательском каталоге Revit Addins 2027; повторная установка сейчас не требуется. При будущем переносе сначала проверить целевой хост и разрешение на установку, использовать пользовательский каталог `%AppData%\Autodesk\Revit\Addins\2027`, не менять системную защиту. Вопрос доверия/подписи и runtime-загрузки остаётся отдельной задачей.

C# capture ограничен сохранённым standalone документом: workshared/cloud/linked root, dirty/unsaved document и design options не поддержаны этим срезом. Простая файловая копия workshared RVT не делает его standalone. Для текущих тестов уже существует подходящая отдельная копия; не отсоединять открытый исходник и не создавать повторные копии. Эти ограничения C# не доказывают полноту будущего Dynamo-адаптера: профиль его поддержки нужно зафиксировать и проверить отдельно.

После решения вопроса загрузки отдельно проверить выбор/отмену команды, read-only capture, install/uninstall и неизменность документа/файла. Сырой JSON не является принятым state калькулятора. Логи, source SHA и независимые сверки сохранять без публикации приватной модели, геометрии и пользовательских путей.

Контракты для переиспользования: [SDK.md](../research/revit-room-export/SDK.md) и [CONTRACT.md](../research/revit-room-export/CONTRACT.md). Факты проверки вносить в существующий протокол, текущий статус — в ТЗ и Issue #13.
