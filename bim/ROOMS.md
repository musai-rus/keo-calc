# Расчёт по Room — draft

Единица расчёта — один Room. Равная площадь не доказывает идентичность помещений.
Если Viewer предоставляет геометрию Room, контур получается сечением именно этого
объекта, а не подбором области из общего среза стен. При отсутствии геометрии
помещение остаётся без результата с объяснением.

Для передачи границ есть кнопки «Задание на выгрузку Room» и «Загрузить границы Room».
Задание содержит идентификаторы помещений и модели; пустые loops нужно заполнить
из подтверждённого источника. Автоматический Revit-экспортёр пока не реализован.
Формат входа:

```json
{
  "version": 1,
  "model": "точный URN из задания",
  "coordinates": "viewer-metres",
  "rooms": [{
    "externalId": "точный externalId из задания",
    "level": "L01",
    "loops": [[[0, 0], [4, 0], [4, 5], [0, 5]]]
  }]
}
```

Координаты — мировые координаты открытой модели Viewer, умноженные на unitScale.
Не подставлять внутренние координаты Revit без регистрации систем координат!
Нельзя переносить URN между файлами, чтобы обойти проверку.
Каждый loop замыкается автоматически. Вложенные контуры задают отверстия по правилу
чётности; несколько непересекающихся внешних контуров допускаются. Повторы Room,
неизвестный externalId, другой уровень, незамкнутые/самопересекающиеся сегменты
отклоняются. Перекрывающиеся в растре Room не рассчитываются.
Файл держится только в памяти текущего экземпляра калькулятора; после повторного
запуска закладки его необходимо загрузить снова.

Физический растр сохраняется для видимости окон. Граница Room не становится
непрозрачной стеной. Ширина расчётного сечения ограничивается собственным Room.
Если автоматический характерный разрез верхнего света выходит за сложный контур,
выдаётся запрос отдельной схемы, а не результат по охватывающему прямоугольнику.

Фонари в BIM-адаптере: круглые и прямоугольные шахты (Б.3). Круг определяется
по многовершинной оболочке; четыре угла квадрата не являются доказательством круга.
Размеры прямоугольника берутся в его собственных осях. Эллипсы, треугольники и
прочие формы сохраняются как кандидаты, но требуют отдельной схемы. Это не полная
поддержка произвольных фонарей: автоматический переход к Б.2 ещё не реализован.
Уже существующий ручной калькулятор Б.2 не менялся.

Привязка проверяет площадь нижнего отверстия на растре Room; при пересечении
границ результат затронутых помещений помечается неполным. Для круглой шахты
используется нижний диаметр, если он передан. Для прямоугольной пока нет адаптера
нижнего отверстия: применяется прежнее явно указанное допущение вертикальной шахты.
Точность проверки принадлежности ограничена размером клетки растра (5 см). Конструктивные допущения прежней версии (включая отверстие в основе фонаря)
не изменены; они остаются в карточке расчёта.

Проверки: `node bim/test-rooms.js`, `node bim/test-geom.js`, обязательные тесты
и сверки из AGENTS.md. `test-bim.js` содержит также регрессию исторического алгоритма
spaces.js; прохождение этих тестов не означает, что он применяется в новом режиме.
Выпуск требует Room-геометрии реальной модели и проверки размещения расчётных точек,
окон и фонарей. Текущая ветка — для разработки, не для нормативного заключения.

Проверка draft в Autodesk Viewer, 15.10.2026: сборка запустилась за 6,7 с;
286 Room имеют externalId, у всех 286 отсутствует собственная замкнутая геометрия.
252 помещения получили статус отсутствия границ, 34 исключены настройкой;
подбор чужих контуров и расчёт по ним не выполнялись. Из 64 кандидатов в фонари
63 распознаны круглыми, один требует отдельной проверки формы. Проверен запуск
и отказ при недостатке данных, но не КЕО по реальным границам Room.
